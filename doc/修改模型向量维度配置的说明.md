# 修复百炼 Embedding 大模型维度溢出的说明

## 报错原因分析
刚才最新报出的错误为 `Value error, dimension for embedding v3 is invalid`，这并不是网络和客户端问题，而是一个硬性的参数边界触发的保护报错。

阿里百炼目前的 `text-embedding-v3` 模型为了保证服务稳定性，支持输出的向量维度最大值为 **1024 维**。但在本应用先前的代码配置项中，默认要求生成的 Embedding 维度为 **1536 维**（这通常是 OpenAI `text-embedding-3-small` 或老的通用模型才独有的规格）。百炼因为受不了这么大的目标要求，直接返回了 HTTP 400 Bad Request 拒绝服务。

## 解决办法及自动执行的操作
为了让你的系统能够平滑对接百炼服务，并保证底层的存储不至于乱套，我连串完成了以下**两步强相关的底层操作**：

1. **下调程序配置预期维度：** 我已经修改了 `application.yaml` 下面定义的候选模型列表 `ai.embedding.candidates`，将向百炼发送请求时的强行约束 `dimension: ${rag.default.dimension}` (其实就是 1536) 缩减为了合法的最大极限 **`dimension: 1024`**。
2. **重塑 PostgreSQL 物理表结构：** 在程序中修改维度是不够的，如果发给 PG 的数组只有 1024 个数，而数据库的表字段限定必须存满 1536 个时，程序入库依然会 SQL 崩溃。我通过 Docker 连入了 `ragent-postgres` 容器，直接敲入了 `ALTER TABLE t_knowledge_vector ALTER COLUMN embedding TYPE vector(1024);` 把底层表的类型容量压档，并且帮你修改了 `schema_pg.sql` 以免以后再被坑。

你只要再重跑一下后端服务，向量引擎的对接就真正彻底大功告成了！
